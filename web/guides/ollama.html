Ollama

A local language model, on port 11434. This is one of the things xoko — the app's brain — can think with, and the only one that costs nothing and sends nothing anywhere.

xoko can also use Claude Code (your own subscription, through the client you logged into in a terminal) or OpenRouter (a key you paste once). Ollama is the one that needs no account at all, and it is slower than either of them on a laptop. All three are honest choices.

Install and run

brew install ollama          # or download from https://ollama.com
ollama serve

Then pull a model. Whatever you pull is what xokolat's picker will offer — it asks Ollama for its list rather than assuming one:

ollama pull qwen3:8b         # a good middle size
ollama list                  # what you have
Route B — headless

At login, without a terminal

Ollama ships its own service definition, so there is no plist to write:

brew services start ollama          # macOS
systemctl --user enable --now ollama # Linux, if installed that way

The macOS desktop app does the same thing when it is running — a menu-bar item and a server on 11434. Either is fine; do not run both.

No GPU-session trap here. Ollama's Metal path does not need a graphical session, so a plain background service works.

Checking it worked

curl -s http://127.0.0.1:11434/api/tags

Then in xokolat: 🔌 inference → Ollama → ↻, and the models you pulled appear in xoko's model picker.

Size the model to the machine, not to the benchmark. A model larger than your free memory does not fail — it swaps, and a reply that would take eight seconds takes four minutes. If xoko feels broken rather than slow, pull something smaller before assuming anything else.
xokolat talks to Ollama through its OpenAI-compatible endpoint at /v1, which is the same adapter it uses for LM Studio, llama.cpp's server, and OpenRouter. Any of them can be added as a service row with a host, a port and a path.
