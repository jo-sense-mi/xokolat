ComfyUI

A graph-based engine that runs on macOS, Linux and Windows, and does a great deal that Draw Things does not — upscalers, restoration, segmentation, and whatever else people have written nodes for.

This is where everything but pictures comes from. Music, voice, video and 3D all reach xokolat through ComfyUI — a workflow here is a node graph, run as published. Get it running with this page, then take a workflow from the library and press it.

It has no server switch to find, because it is a server: starting ComfyUI starts an HTTP API on port 8188 and a web page on the same port. The web page is a client, not the program.

Install it

ComfyUI is a Python program. Whatever else you do, give it its own virtual environment — its dependency set is large, opinionated about torch versions, and not something to share with anything.

git clone https://github.com/comfyanonymous/ComfyUI.git
cd ComfyUI
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt

On an Apple Silicon Mac the default install already uses the GPU through Metal; there is no CUDA step and no extra index URL. On a Linux box with an NVIDIA card, install torch from the CUDA index first, as ComfyUI's own README describes for your driver version.

Route A — simplest

Run it in a terminal

.venv/bin/python main.py --listen 127.0.0.1 --port 8188

Leave the terminal open. --listen 127.0.0.1 is worth typing even though it is close to the default: ComfyUI has no authentication of any kind, and anything that can reach the port can run arbitrary graphs — including ones that read files.

Route B — headless

Run it at login

Same two mechanisms as anything else: a launch agent on macOS, a systemd user unit on Linux. Both below.

macOS — a launch agent

Save as ~/Library/LaunchAgents/lat.xoko.comfyui.plist, replacing YOU and the path to your clone. launchd does not expand ~.

<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE plist PUBLIC "-//Apple//DTD PLIST 1.0//EN"
  "http://www.apple.com/DTDs/PropertyList-1.0.dtd">
<plist version="1.0">
<dict>
  <key>Label</key>
  <string>lat.xoko.comfyui</string>
  <key>ProgramArguments</key>
  <array>
    <string>/Users/YOU/src/ComfyUI/.venv/bin/python</string>
    <string>/Users/YOU/src/ComfyUI/main.py</string>
    <string>--listen</string><string>127.0.0.1</string>
    <string>--port</string><string>8188</string>
  </array>
  <key>WorkingDirectory</key>
  <string>/Users/YOU/src/ComfyUI</string>
  <key>RunAtLoad</key><true/>
  <key>KeepAlive</key><true/>
  <key>StandardOutPath</key><string>/Users/YOU/Library/Logs/comfyui.log</string>
  <key>StandardErrorPath</key><string>/Users/YOU/Library/Logs/comfyui.err.log</string>
</dict>
</plist>
launchctl bootstrap gui/$(id -u) ~/Library/LaunchAgents/lat.xoko.comfyui.plist
A user agent here too, for the same reason. On an Apple Silicon Mac, ComfyUI renders through Metal, and Metal wants the logged-in graphical session. gui/$(id -u) puts it there. Do not run it under sudo.

WorkingDirectory matters more than it looks: ComfyUI resolves models/, custom_nodes/ and output/ relative to where it runs, and started from the wrong folder it comes up with an empty model list.

Linux — a systemd user unit

Save as ~/.config/systemd/user/comfyui.service:

[Unit]
Description=ComfyUI
After=network.target

[Service]
WorkingDirectory=%h/src/ComfyUI
ExecStart=%h/src/ComfyUI/.venv/bin/python main.py --listen 127.0.0.1 --port 8188
Restart=on-failure

[Install]
WantedBy=default.target
systemctl --user daemon-reload
systemctl --user enable --now comfyui
loginctl enable-linger $USER   # so it runs when you are not logged in

Apple Silicon: one node you should not skip

ComfyUI on a Mac renders through Metal, and that works — for models stored in plain 16-bit weights. The interesting ones are not. Modern video and image checkpoints ship quantized (int8, fp8, nvfp4), and those formats were designed around NVIDIA hardware: the operations they need have no Metal implementation. PyTorch's answer is to quietly run them on the CPU instead.

Quietly is the problem. Nothing errors. The render just takes hours, and the log line that says why scrolls past once at startup.

UserWarning: The operator 'aten::_int_mm' is not currently supported on
the MPS backend and will fall back to run on the CPU.

ComfyUI-AppleSilicon-FP8 fixes it. It adds no nodes and changes no workflow — it patches the maths at startup and everything you already have gets faster. It also moves large text encoders back onto the GPU, which is worth as much as the rest.

cd ~/ComfyUI/custom_nodes
git clone https://github.com/pawel-mazurkiewicz/ComfyUI-AppleSilicon-FP8
~/ComfyUI/.venv/bin/pip install -r ComfyUI-AppleSilicon-FP8/requirements.txt

Restart, and it prints one line saying what it found:

[AppleSilicon-FP8] capabilities: macOS=26.6.2, torch=2.12.0, mps=yes,
compile_shader=yes, chip=Apple M5 Pro, matrix_units(M5+)=yes, ninja=yes
Read that line. ninja=no means the fast Metal kernels were never built and you are on the slower fallback — ninja is in its requirements, so that usually means the install did not finish. The M5 and macOS 26 entries are what unlock the native int8 kernel; older machines still get the correctness fixes, just less of the speed.

Checking it worked

curl -s http://127.0.0.1:8188/system_stats

That answers with JSON describing the machine and the device it will render on. Opening http://127.0.0.1:8188 in a browser gets you ComfyUI's own graph editor, which is the easiest way to confirm your models are where it expects.

Models go under the clone's models/ folder, split by kind (checkpoints/, loras/, controlnet/…). If you already have a library elsewhere, extra_model_paths.yaml points at it instead of duplicating it.
